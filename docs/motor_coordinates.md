# 电机坐标系、安装方向与零偏说明

本文说明实机封装 [`motor::Motor`](../realistic/movement/include/motor.hpp) 使用的坐标与角度约定。对外的 `MotorCtrl` 和 `MotorState` 使用统一腿部坐标、输出轴侧单位；SDK 的 `MotorCmd` 和 `MotorData` 使用电机原生方向、转子侧单位。代码示例使用 C++17。

## 1. 机器人坐标系与腿部平面

| 轴 | 正方向 |
|---|---|
| $x$ | 机器人前进方向 |
| $y$ | 机器人右侧 |
| $z$ | 机器人正上方 |

轴向相对机体定义；机体倾斜后，$+z$ 随机体倾斜，不自动保持世界竖直方向。本文只规定机体轴向，机体原点由上层模型确定。

每条腿使用与机体轴向一致的局部 $xz$ 平面，局部原点取该腿髋轴在运动平面内的投影。观察方向统一为：**站在机器人右侧，向左看**，即沿 $-y$ 方向观察。

```text
                   +z（向上）
                    ↑
                    |
                    O ─────────→ +x（前进）

                    O 为髋轴原点

        观察者位于 +y 一侧，面向腿部 xz 平面
```

连杆从原点指向 $+x$ 时，统一腿部角度为零。从上述视角观察，逆时针为正：

$$
q=\operatorname{atan2}(z,x)
$$

例如，连杆指向 $+z$ 时，$q=+\pi/2$；指向 $-z$ 时，$q=-\pi/2$。这里的 $(x,z)$ 是该主动连杆末端相对其髋轴的坐标，不能用足端极角替代每个主动连杆的角度。

`atan2` 给出角度的主值。需要连续运动时应保留连续角度分支；当前 `Motor` 类不会自动将角度限制或归一化到某个区间。

“前、右、上”构成左手坐标系，即 $\boldsymbol e_x\times\boldsymbol e_y=-\boldsymbol e_z$。平面角度按上述定义计算即可；与右手坐标系的三维旋转、姿态或动力学公式对接时，需要明确坐标转换。

## 2. 电机原生方向与安装方向

每台电机的原生正方向定义为：**正视该电机输出侧时，输出轴逆时针转动为正**。

由于电机对称安装，电机原生正方向不一定与统一腿部正方向一致。引入安装方向系数 $s$：

| 输出侧朝向 | 原生正转在统一右侧视角中的方向 | $s$ | `direction_` |
|---|---|---|---|
| 朝机器人右侧 | 逆时针 | $+1$ | `true` |
| 朝机器人左侧 | 顺时针 | $-1$ | `false` |

按每台电机输出侧的实际朝向配置，不能仅凭所在腿是左腿还是右腿决定。同一条腿中的两台电机也应分别确认。

`direction_` 是布尔值，不是直接保存 $\pm1$ 的数值系数：

```cpp
const float s = direction_ ? 1.0f : -1.0f;
```

构造参数应传 `true` 或 `false`。C++ 中 `-1` 转为 `bool` 仍为 `true`，不能用 `-1` 表示反向安装。

## 3. 零偏 offset 的定义

零偏定义为：

$$
o=\mathrm{offset}=\text{编码器零位方向}-\text{机器人 }+x\text{ 方向}
$$

这里的“相减”表示有向角：从 $+x$ 转到选定编码器零位所对应的连杆方向，按该电机输出侧观察的逆时针方向为正。`offset_` 使用**输出轴侧 rad**，每台电机独立标定。

“编码器零位方向”指选定的转子零位分支对应的连杆方向，不是直接拿转子轴上的标记与机体 $+x$ 比较。由于减速器存在，必须同时明确转子侧与输出轴侧的对应关系。

设减速比为 $N=6.33$，并定义：

| 符号 | 含义 |
|---|---|
| $r$ | 电机原生方向下的转子编码器角度，rad |
| $a$ | 电机原生方向下，连杆相对 $+x$ 的输出轴角度，rad |
| $q$ | 统一腿部方向下，连杆相对 $+x$ 的输出轴角度，rad |
| $o$ | 电机原生方向下的输出轴零偏，rad |
| $s$ | 安装方向系数，$+1$ 或 $-1$ |

以下绝对角度公式均以转子所属圈数和零位分支已经确定为前提。

当编码器读数 $r=0$ 时，连杆在电机原生方向下的角度为 $a=o$。转子继续转动 $r$ 后：

$$
a=o+\frac{r}{N},\qquad q=s\left(o+\frac{r}{N}\right)
$$

因此，零偏既不是当前姿态的实时误差，也不是构造对象时自动读取的当前位置。固定安装和选定参考分支后，它是一个标定参数。

### 3.1 连杆指向 +x 时的绝对编码器目标

连杆指向 $+x$ 时，$q=0$，因此：

$$
r_x=-No
$$

这与 $s$ 无关：改变角度正方向，不改变同一物理零位对应的原生编码器目标。

### 3.2 从当前位置回到 +x 的相对位移

若当前位置的转子角度为 $r=\mathrm{data\_.q}$，则回到 $+x$ 所需的转子侧相对位移为：

$$
\Delta r=r_x-r=-\mathrm{data\_.q}-N\,\mathrm{offset}
$$

所以 `-data_.q - offset_ * 6.33f` 表示**相对位移**。当前封装向 SDK 的 `cmd_.q` 写入的是**绝对位置目标**，回到 $+x$ 时应写入 `-offset_ * N`，不再减去当前读数。

### 3.3 根据已知姿态标定零偏

将连杆置于已知统一角度 $q_{\mathrm{cal}}$，读取对应转子角度 $r_{\mathrm{cal}}$，则：

$$
o=sq_{\mathrm{cal}}-\frac{r_{\mathrm{cal}}}{N}
$$

若标定姿态就是连杆指向 $+x$，则简化为：

$$
o=-\frac{r_{\mathrm{cal}}}{N}
$$

标定读数与后续控制必须采用同一个转子参考分支。重新安装、重新选择编码器参考分支后，需要重新确认零偏。

## 4. 命令与反馈的完整换算

### 4.1 命令：统一腿部坐标到 SDK 转子坐标

由 $q=s(o+r/N)$，且 $s^2=1$，得到：

$$
r^*=N(sq^*-o)
$$

速度、前馈力矩与增益换算为：

$$
\dot r^*=sN\dot q^*,\qquad
\tau_r^*=\frac{s\tau_q^*}{N}
$$

$$
K_{p,r}=\frac{K_{p,q}}{N^2},\qquad
K_{d,r}=\frac{K_{d,q}}{N^2}
$$

力矩换算忽略传动损耗。位置、速度和力矩需要使用同一个方向系数；增益不反号。零偏是常数，只进入位置换算。

零偏在括号中的符号固定为负。反向安装时，应写成 $N(-q^*-o)$，不能写成 $-N(q^*-o)$，后者会错误地把零偏也反号。

对应当前 `editCmd()` 换算部分的等价写法：

```cpp
const float N = queryGearRatio(cmd_.motorType);
const float s = direction_ ? 1.0f : -1.0f;

cmd_.q   = (s * target.q - offset_) * N;
cmd_.dq  = s * target.dq * N;
cmd_.tau = s * target.tau / N;
cmd_.kp  = target.kp / (N * N);
cmd_.kd  = target.kd / (N * N);
```

其中 `target` 是根据控制模式筛选过的参数。在速度、阻尼和力矩模式中，位置增益为零，因此转换后的位置字段不产生位置控制作用。

### 4.2 反馈：SDK 转子坐标到统一腿部坐标

$$
q=s\left(\frac{r}{N}+o\right),\qquad
\dot q=\frac{s\dot r}{N},\qquad
\tau_q\approx sN\tau_r
$$

当前 `getData()` 在反馈有效性检查之后执行：

```cpp
const float N = queryGearRatio(cmd_.motorType);
const float s = direction_ ? 1.0f : -1.0f;

return MotorState{
    s * (data_.q / N + offset_),
    s * data_.dq / N,
    s * data_.tau * N,
    data_.temp,
    data_.merror,
    true
};
```

因此，上层调用 `editCmd()` 前和 `getData()` 后，都不应再次施加方向、零偏或减速比换算。否则会重复变换。

## 5. 数值例子与一致性检查

取 $N=6.33$、$o=0.2\,\mathrm{rad}$，两种安装均要求统一角度 $q^*=0.5\,\mathrm{rad}$：

| 项目 | 正向安装 $s=+1$ | 反向安装 $s=-1$ |
|---|---|---|
| 转子目标 $r^*$ | $(0.5-0.2)\times6.33=1.899$ | $(-0.5-0.2)\times6.33=-4.431$ |
| 理想到位后反馈 $q$ | $1.899/6.33+0.2=0.5$ | $-(-4.431/6.33+0.2)=0.5$ |
| 指向 $+x$ 时的转子目标 $r_x$ | $-1.266$ | $-1.266$ |
| 从该目标位置回到 $+x$ 的转子位移 $\Delta r$ | $-3.165$ | $3.165$ |

两个例子都能从原生转子目标还原出相同的统一腿部目标。

一般情况下，将命令换算再代入反馈换算，也应还原原值：

$$
s\left(\frac{N(sq-o)}{N}+o\right)=q
$$

这检验的是坐标换算的一致性，不代表实机没有跟踪误差、传动损耗或标定误差。

## 6. 单圈转子编码器的上电圈数问题

若上电时只能获得转子单圈角度 $\phi$，实际连续转子角度存在多个候选值：

$$
r=\phi+2\pi k,\qquad k\in\mathbb Z
$$

相应的统一腿部角度候选为：

$$
q_k=s\left(o+\frac{\phi+2\pi k}{N}\right)
$$

相邻候选位置在输出轴侧相差：

$$
\left|q_{k+1}-q_k\right|=\frac{2\pi}{6.33}
\approx0.993\,\mathrm{rad}\approx56.87^\circ
$$

单次单圈读数不能区分这些位置。`offset_` 描述选定零位与 $+x$ 的固定关系，不能独立确定未知整数 $k$。

上层需要通过已知上电姿态、足够窄且已知的关节角度区间、回零过程或额外位置观测，选择唯一分支。若运行期间读数仍是单圈值，还需要展开跨圈角度；展开过程不能自动解决上电前未知的圈数。

当前 `Motor` 类直接转换 SDK 返回的 `data_.q`，没有实现上述分支识别或角度展开，也没有自动修正 SDK 的位置参考。实际对接时，要确认反馈角度、命令目标与 `offset_` 都使用同一套参考；若驱动在重启时重建参考，需要同步调整标定映射。

不要为了让角度落入某个区间而单独对 `offset_` 或转子目标取模；改变分支时，必须同步保持整套位置参考的一致性。

## 7. 与现有文档、仿真的关系

[`motor_driver.md`](motor_driver.md) 说明实例创建、控制模式与通信流程；本文补充其方向和零偏约定。

[`leg_kinematics.md`](leg_kinematics.md) 描述仿真模型，采用机体“前、左、上”和局部“向前、向下”的坐标约定，与本文的实机约定不同。若原点与姿态一致，两套机体位置坐标满足：

$$
x_{\mathrm{sim}}=x_{\mathrm{real}},\qquad
y_{\mathrm{sim}}=-y_{\mathrm{real}},\qquad
z_{\mathrm{sim}}=z_{\mathrm{real}}
$$

仿真局部平面中的向下坐标对应本文的 $-z$。仿真关节还带有 CAD 初始装配角，不能仅凭坐标轴符号把仿真关节角直接当作本文的连杆绝对角，也不能照搬其按腿名给出的方向系数。

[`motor_model.md`](motor_model.md) 中若使用转子侧机械零位 $q_{r,0}$，则与本文的零偏关系为：

$$
q_{r,0}=-No,\qquad r=q_{r,0}+sNq
$$

该写法与本文 $r=N(sq-o)$ 完全等价；两种零偏参数的单位和符号不同，不能混用。
